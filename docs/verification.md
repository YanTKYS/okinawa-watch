## Issue #3：日付未確認の催しと掲載の新しさ

評価日を **2026-11-03（JST）** に固定し、初期20件をブラウザと同じ `web/display.js` で判定した。公開日・取得日から開催年や終了日を補っていない。[判定ログ](logs/initial-display.json)にタイトル・URL・状態・参照日・経過日数・非表示理由を保存した。

| 表示条件 | 件数 |
|---|---:|
| 通常の「すべて」 | 17 |
| 「催し（日付未確認）」 | 15 |
| 日付確認済みの「今だけ」（通常表示） | 0 |
| 終了日経過で通常表示から外す | 2 |
| 古い日付未確認情報で通常表示から外す | 1 |
| 両方の表示チェックを有効にした「すべて」 | 20 |

- 年省略の11月7・8日、11/8、11/28・29日の催しは「開催日未確認」として専用入口から見つかる。「今だけ」の空状態からも移動できる。街分野のオープニングセレモニーもタイトルの手掛かりで含める。
- 確認済みの終了日はJSTで翌日から外す。確認できた将来の開催日は、公開日が古くても表示する。年省略の10月末の催しを推測で終了済みにはせず、「開催日未確認」と元記事確認の注意を付ける。
- 未確認の催し・期間限定の話題は掲載から14日以内を通常表示する。公開日が不明なら初回取得日を使い、最終再取得日で新しさを更新しない。両日付が不明なら通常表示から外す。設定の閾値を超えた場合は終了の断定と区別し、復元用チェックと理由を提供する。
- 初期データの古い「7日ごろまで大雨が続く可能性」は、未確認の期限に関する古い掲載情報として外れる。隠した理由は `old_unverified`。開催日不明の古いイベント・期限不明の特売もテストデータで確認した。
- 過去掲載を戻した場合は、通常の記事、古い・掲載日不明の未確認情報、終了日経過の順とし、各区分で公開日（なければ初回取得日）の新しい順に並べる。
- 14日の最終日は含め、JSTの翌日0時を越えると外れる。0日設定、日付が不明な場合、未来の公開日を開催日と誤認しないこと、未来開催が確認済みの記事を古さで外さないことをテストした。
- 画面の「通常表示から外す情報・理由」と、CI artifactの `display-report.json` で検証できる。前者は閲覧日の判定、後者はCI実行日の記録であり、日付が違えば件数も変わる。絞り込みによる非表示は鮮度ログに含めない。

閾値は編集方針であり、14日以内の催しが開催中とは限らない。イベント・期間限定の判定も設定した分野／タイトルの手掛かりなので誤分類があり、設定で調整する。日付を確認するための記事本文取得、AI分類、価格の補完は追加していない。

## 既知の制約

- 分野は配信カテゴリを優先するが、「今だけ」「お得」はタイトルだけで判定する。日付が本文にしかない催しは「今だけ」にならない。年の補完、本文の期限抽出、価格抽出、生成AIは行わない。
- 除外キーワードは誤除外がある。例：街の発見記事に「基地」が含まれる場合。`exclude_keywords` を調整し、artifactの監査ログで確認する。本文中の政治・事件の検出はしない。
- 日付は年を含む単一日、または両端が完全な日付の明示的な範囲だけ。省略を含む期間、繰り返し・「から」「以降」は控えめに分類対象外。開始時刻・締切時刻は推測せず、終了日の翌日（JST）から非表示にする。
- 過去データは90日・500件に制限。ページ送り・過去記事の遡及収集はしない。同一URLのフィード訂正は次回収集時に更新する。
- robots.txtはPython標準のRobotFileParserで解釈。特定サイトの拡張規則までの完全互換は保証しない。取得できない場合はフィード収集を見送る。
- 取得先の変更、robotsや利用条件、RSS URLの継続性は保証できない。記事URLは情報源の申告を使い、本文ページへの疎通確認は行わない。
- 全源失敗でも前回データを配信できるよう収集コマンドは正常終了し、ログに警告を出す。ジョブ成功だけで判断せず源ごとの `status` を確認する。監査ログは30日で失効するため必要なら取得して保管する。
- データブランチの保護・Actionsの無効化・Pages権限設定によって初回運用が止まる可能性がある。初回は `main` で手動実行して確認する。

## 再実行

```sh
python3 -m unittest discover -s tests -v
node --check web/app.js
node --test tests/display.test.cjs
python3 scripts/watch.py collect
python3 scripts/watch.py build
python3 scripts/watch.py build --sample --output work/sample-site
```

任意のUI検証はPlaywright PythonとChromiumが必要（本番の依存には含めない）。`python3 -m http.server 8000 --directory work` を起動して `python3 tests/ui_smoke.py`。スクリプトは `/usr/bin/chromium` を使用する。画面テスト用の架空情報はローカルHTTP応答に注入するだけで、記事データには保存しない。
